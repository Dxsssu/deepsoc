# TTT 更新机制变更说明（汇报版）

## 1. 文档目的
用于记录本次 TTT（Traceback Task Tree）后续更新机制调整，明确：

1. 改动前：仅允许修改节点状态（结构锁）
2. 改动后：移除结构锁，并更新 Captain 后续轮次指令

文档时间：2026-04-13  
适用范围：DeepSOC 后端 TTT 维护链路（Captain 主流程）

---

## 2. 改动前机制（仅修改节点状态）

### 2.1 核心规则
- Captain 在后续轮次会读取最新 TTT 和 LLM 候选树。
- 系统启用“结构锁”逻辑：仅同步节点 `status`，不允许改变树结构。
- 禁止新增/删除/重命名节点，禁止调整层级。

### 2.2 实现方式
- Captain 侧调用 `apply_status_updates_from_candidate(base, candidate)`：
  - `base`：上一版 TTT（结构基准）
  - `candidate`：LLM 本轮输出
  - 结果：只从 `candidate` 吸收状态到 `base`，结构保持不变

### 2.3 对应代码（改动前）
- `app/services/captain_service.py`
  - 存在结构锁分支及日志：`已启用TTT结构锁，仅同步节点状态`
  - 使用 `apply_status_updates_from_candidate(...)`
- `app/services/ttt_service.py`
  - `apply_status_updates_from_candidate(...)` 负责“仅状态更新”
- `app/prompts/default_prompts.py`
  - Captain 规则中存在“第二轮开始只能更新已有节点status，禁止调整树结构”

### 2.4 机制特点
- 优点：结构稳定、可控，节点 ID 稳定性高。
- 限制：当出现新证据或新假设时，难以自然扩展任务树，表达能力受限。

---

## 3. 改动后机制（移除结构锁，允许谨慎结构更新）

### 3.1 核心规则
- 移除 Captain 的“结构锁”执行路径。
- Captain 后续轮次读取：
  - 最新 TTT 快照
  - 上一轮 Summary
  - 历史任务信息
- 允许在必要时：
  - 更新节点状态
  - 更新树结构（新增/合并/拆分/重命名节点）
  - 更新节点任务信息
- 约束原则：**最小改动优先**
  - 能不改结构就不改
  - 能小改就不大改
  - 仅在新证据/新假设/原结构不足时调整

### 3.2 实现方式
- Captain 不再调用 `apply_status_updates_from_candidate(...)`。
- LLM 输出的 TTT 进入 `normalize_ttt_tree(...)` 后直接保存新快照。
- 同时通过提示词增加谨慎改动约束与节点 ID 稳定性要求。

### 3.3 对应代码（改动后）
- `app/services/captain_service.py`
  - 移除 `apply_status_updates_from_candidate` 的 import 和调用。
  - 更新后续轮次指令，明确“可必要结构调整 + 最小改动优先”。
  - 新增约束：尽量保持原 `node_id` 稳定，仅为新增节点分配新 ID。
- `app/prompts/default_prompts.py`
  - 将“仅可改状态”更新为“可必要改结构，但最小改动优先”。
- `docs/TTT_Design.md`
  - 文档同步：后续轮次允许必要结构调整，并强调最小改动策略。

---

## 4. 前后对比（汇报摘要）

| 对比项 | 改动前 | 改动后 |
|---|---|---|
| 后续轮次是否可改结构 | 否 | 是（必要时） |
| 结构锁 | 启用 | 已移除 |
| Captain 更新权限 | 仅状态同步 | 状态 + 结构 + 节点任务信息 |
| 风险控制策略 | 强约束（不改结构） | 最小改动优先（谨慎改） |
| 对新证据适应性 | 较弱 | 增强 |

---

## 5. 影响与说明

### 5.1 正向影响
- TTT 能随着证据演进动态修正，表达能力更强。
- 任务规划更贴近实战（可新增必要调查分支）。

### 5.2 风险与控制
- 风险：结构可变后，历史链路追踪复杂度上升。
- 已加控制：
  - 仅允许必要改动
  - 最小改动优先
  - 倡导保留既有 `node_id`（新增节点再分配新 ID）

---

## 6. 本次变更结论
- 已完成从“状态锁定型更新”到“谨慎演进型更新”的机制升级。
- 本次升级不会改变 TTT 三层结构约束（L1/L2/L3），但允许在该约束内进行必要结构演进。
- 变更重点已覆盖代码、提示词、设计文档三层，便于持续维护与对外汇报。
